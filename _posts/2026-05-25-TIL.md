## 1. GitHub Pages 블로그 초기 생성하기

Jekyll Chirpy 테마는 기본 템플릿을 복사하여 손쉽게 시작할 수 있도록 `chirpy-starter` 리포지토리를 제공합니다.

1. **GitHub에서 템플릿 복사**: [Chirpy Starter Repository](https://github.com/cotes2020/chirpy-starter)로 이동한 뒤, 우측 상단의 **`Use this template`** -> **`Create a new repository`**를 클릭합니다.
2. **리포지토리 이름 설정**: 자신의 GitHub ID를 활용하여 반드시 **`개인ID.github.io`** 형식으로 이름을 지정해야 메인 도메인 주소로 블로그가 연결됩니다. (예: `sang9831.github.io`)
3. **Repository 생성**: Public 상태로 두고 생성을 완료합니다.

---

## 2. 초기 배포 시 주요 문제점 및 해결 방법

템플릿 생성 후 블로그 주소(`https://username.github.io`)로 접속했을 때, **화면이 완전히 깨지거나 흰 바탕에 텍스트만 나오는 현상**이 빈번하게 발생합니다. (주소 뒤에 `index.html`을 붙여야만 임시로 정상 출력되는 현상)

이는 블로그의 자산(CSS, JS 등) 경로를 설정하는 파일과 GitHub Pages의 빌드 방식이 일치하지 않아 발생하는 문제입니다. 아래 두 가지 설정을 반드시 완료해야 합니다.

### ① `_config.yml` 파일의 경로 수정
프로젝트 루트에 있는 `_config.yml` 파일을 열고 메인 도메인 구조에 맞게 경로를 수정합니다.
* **url**: 끝에 슬래시(`/`)를 제외한 본인의 전체 블로그 도메인을 적습니다.
* **baseurl**: 사용자 메인 페이지로 배포할 때는 반드시 빈 문자열(`''`)로 설정해야 스타일 경로가 꼬이지 않습니다.

```yaml
url: '[https://<username>.github.io](https://<username>.github.io)'
baseurl: ''

```

### ② GitHub Pages 배포 소스(Source) 변경

Chirpy 테마는 내장된 스크립트를 통해 원격에서 자동 빌드 및 배포(CI/CD)를 수행합니다. 따라서 기존의 브랜치 기준 배포 방식을 **GitHub Actions**로 변경해야 합니다.

1. 본인의 GitHub 리포지토리 상단의 **Settings** 메뉴로 이동합니다.
2. 왼쪽 사이드바에서 **Pages**를 클릭합니다.
3. **Build and deployment** 섹션의 **Source** 설정을 `GitHub Actions`로 변경합니다.

> 💡 **확인하기**: 설정을 바꾼 후 리포지토리의 **Actions** 탭에서 빌드가 성공(초록색 체크)했는지 확인한 뒤, 브라우저에서 강제 새로고침(`Ctrl + F5` 또는 `Cmd + Shift + R`)을 누르면 메인 도메인에서도 정상적인 테마를 볼 수 있습니다.

## 3. 로컬(VS Code) 개발 환경 연동하기

매번 GitHub 웹사이트에서 파일을 수정하는 것은 비효율적입니다. 내 컴퓨터의 VS Code에서 코드를 수정하고 원격에 푸시하는 파이프라인을 구축해 둡니다.

### ① 리포지토리 클론 (Clone)

컴퓨터에 적절한 폴더를 생성하고 터미널을 열어 원격 저장소의 파일을 다운로드합니다.

```bash
git clone [https://github.com/<username>/<username>.github.io.git](https://github.com/<username>/<username>.github.io.git)

```

클론이 완료되면 VS Code에서 해당 폴더를 엽니다 (`File` -> `Open Folder`).

### ② 블로그 포스트(Post) 작성 규칙

블로그 글은 반드시 프로젝트 루트의 **`_posts`** 폴더 내에 작성해야 하며, 아래의 두 가지 규칙을 엄격히 준수해야 에러가 나지 않습니다.

1. **파일명 규칙**: 반드시 `YYYY-MM-DD-제목.md` 포맷이어야 합니다. (예: `2026-05-24-my-first-post.md`)
2. **Front Matter 작성**: 마크다운 파일 최상단에 글의 메타데이터를 기입합니다. 콜론(`:`) 뒤에는 반드시 **한 칸의 공백**이 필요합니다.

```markdown
---
title: "포스팅 제목 입력"
date: 2026-05-24 12:00:00 +0900
categories: [대분류, 소분류]
tags: [태그1, 태그2]
---
여기서부터 본문을 마크다운 문법으로 자유롭게 작성합니다.

```

### ③ 수정한 코드 반영 및 배포 (Push)

글 작성을 마쳤다면 VS Code 내장 터미널을 통해 아래 명령어를 순서대로 입력하여 블로그를 업데이트합니다.

```bash
git add .
git commit -m "Feat: 신규 포스팅 업로드"
git push origin main

```

## 4. 참고: `_posts` 폴더 내 `.placeholder` 파일이란?

처음 프로젝트를 다운로드하면 `_posts` 폴더 안에 내용이 비어 있는 `.placeholder` 파일이 들어있습니다.

Git 시스템은 특성상 **내용물이 없는 빈 폴더는 인식하지 않고 무시**합니다. 따라서 초기에 포스트가 하나도 없을 때 `_posts` 폴더 자체가 공중분해 되는 것을 막기 위해 테마 개발자가 임시로 넣어둔 '자리 지킴이(Dummy)' 파일입니다. 로컬에서 실제 포스트 파일을 하나 이상 생성했다면 이 파일은 **지워도 무방**합니다.

## 5. 지속 가능한 블로그 관리를 위한 일일 루틴

로컬 환경 세팅이 완료되었다면, 앞으로 새 글을 쓰거나 수정할 때는 아래의 3단계 루틴만 기억하시면 됩니다.

1. **최신 상태 동기화**: 작업 시작 전 원격의 변경 사항을 가져옵니다.
```bash
git pull origin main

```


2. **글 작성**: `_posts` 폴더에 양식에 맞춰 `.md` 파일 추가 및 수정
3. **배포**: 저장 후 깃허브에 반영
```bash
git add . && git commit -m "Update blog" && git push origin main

```
